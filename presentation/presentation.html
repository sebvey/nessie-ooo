01 · Pourquoi Nessie

Traiter la donnée comme du code

Le problème

  • La pipeline écrit directement dans les tables de prod.
  • La mauvaise donnée est visible tout de suite.
  • Tester en isolation, revenir en arrière, coordonner plusieurs tables : douloureux.

L'idée

Git, mais pour les données.

Nessie versionne le catalogue (les pointeurs de métadonnées), pas les fichiers. On récupère branch / commit / merge / tag sur des tables Iceberg — sans copier la donnée.

Ce que ça débloque

  • Isolation — transformer & tester sur une branche.
  • Merge atomique — promotion tout-ou-rien.
  • Rollback — revenir à un commit précédent.
  • Reproductibilité — auditer via un tag.

Brancher → tester → ne merger que si c'est vert. La mauvaise donnée n'atteint jamais main.

Control plane (brancher / merger / tag) = API Nessie · data plane (lire/écrire sur la branche) = PyIceberg, la branche est dans l'URI. dbt ne fait qu'une chose : transformer + tester la branche qu'on lui désigne.

04 · Le scénario de démo

Trois actes

Acte 1 — le run qui marche
$ mise run pipeline

Branche → ingestion → dbt build vert → merge dans main + tag.

✓ main est mis à jour, promotion taguée
Acte 2 — le run qui casse · le moment fort
$ mise run pipeline-bad

Mauvaise donnée (montant négatif, client null) → tests rouges → pas de merge, alerte, branche conservée.

⛔ main est resté propre
Acte 3 — explorer & prouver
$ mise run branches
$ mise run notebook

Basculer main ↔ branche -bad dans le notebook · rejouer avec mise run dbt-inspect.

# préparation : mise run stack-reset && mise run stack-up → ardoise vierge, main sans aucune table

05 · Maturité

Qui gère vraiment les branches Nessie ?

Maturité de l'intégration Nessie — surtout écrire/lire sur une branche ≠ main — pas du support Iceberg en général.

Spark—
✓ Mature · natif
Extensions SQL Nessie : CREATE / MERGE BRANCH en SQL. La voie canonique. Contrepartie : JVM, lourd.
PyIcebergingestion + marts
✓ Mature
Branche dans l'URI (/iceberg/<branche>), respecte overrides.uri → n'importe quelle branche, en lecture et écriture.
DuckDBtransformations
⚠ Pas mature
main uniquement : le client ignore overrides.uri et double le prefix (#1145) ; pas de CREATE OR REPLACE. On a rusé : DuckDB calcule, PyIceberg écrit sur la branche.
Trino—
⚠ Pas mature
Branche = propriété statique du catalogue, pas par session/requête ; pas de branch en SQL (#24134).

Pour un workflow multi-branches dynamique, seuls Spark (natif, lourd) et PyIceberg (léger, via l'URI) sont prêts. D'où notre choix : PyIceberg pour les branches + DuckDB pour le calcul.
